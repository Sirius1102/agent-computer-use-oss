# 电脑操控快速上手

这是一份给第一次接触本工具的 Agent 的短指南。目标是让每次桌面操作都经过“看清楚 → 找到目标 → 执行动作 → 读回结果”，而不是凭记忆猜窗口或坐标。

v4.5.0 起，工具会记录每次调用，并在独立调用重叠时向 stderr 发出提醒。提醒不会阻断动作；--json 的 stdout 仍保留给 JSON。调用者身份来自受约束的环境字段，缺失时会显示 unknown；这些记录用于审计和并发发现，不等于桌面独占证明。

v4.5.1 起，wheel 默认仍按 raw delta 解释并使用竖向轴；省略 amount 时仍为 -120 raw delta。--unit notches 按每格 120 换算，使用时须显式给出 amount；--axis horizontal 选择横向滚动。负值分别表示竖向向下、横向向左。

v4.5.2 起，`wheel ... --to <sel>` 会校验实际滚动点位于该窗口且命中该顶层窗口；未指定目标时仍滚动当前光标所在位置。`--at <sel>` 必须和明确的 `[x y]` 一起使用，不再把窗口中心当作滚动控件。`--focus-first` 仍须显式指定，点击前和点击后都会复核落点；滚轮回执会列出 `SendInput` 插入计数，但不会把它说成界面已生效。

v4.5.3 起，只有需要验证滚动效果时才显式加 `--verify-scroll`（需目标选择器和 `amount x y`）：优先读目标点 UIA `ScrollPattern` 位置；已在请求方向的边界会报告 `at-boundary`，不注入。UIA 不可用时可给目标窗口内的 `--expect-change x,y,w,h`，结果只代表该局部像素变化。需要确认具体条目时可用 `--expect-visible-text <needle>`；它只在目标窗口内找到新出现的可见 UIA 名称时报告内容出现。最多 13 次采样，回执说明实际等待与采样数；验证无效果、目标变化或不可判定会失败退出，不重试。

v4.5.5 起，使用 `--to` 的动作命令遇到未命中的数字 PID，会提示重新运行 `wins` 并选当前 PID；数字选择器仍只匹配 PID，不会退回标题匹配。v4.5.4 起，`shot [outPath]` 只截取整个虚拟屏幕，最多接受一个输出路径；未知旗标和多余位置参数会在读取屏幕或写图前拒绝，并提示正确用法。局部原尺寸截图用 `rect 0 2010 400 80 <outPath> --fit 0`；用同图的 `.map.txt` 通过 `imgclick` 点击或用 `unmap` 只换算坐标。窗口、模态或布局变化后重新截图，不沿用旧映射。

## 五分钟速查（先读这页）

**新手必读（Top 5）**

- `find` 先 UIA 再 OCR、自报来源——取坐标的第一选择（完整阶梯：`uia-find` → `find-text` → `imgclick`，别跳级）。
- 六道守卫：前台 / 内容 / 落点 / 遮挡 / 动作后断言 / 未知标志阻断——被 `REFUSED` 先读原因，不要用 `--force` 掩盖定位问题。
- 坐标是真实屏幕像素（150% 缩放已由工具处理）；对不上先怀疑坐标系，不要“再点一次试试”。
- 回显里的证据行（`hit-window` / `occluded=` / `centre=`）是动作有没有落到对的地方的凭据——不要 `grep` 掉（要压输出用 `--json`）。
- `type` 可直接打中文（SendInput Unicode，不经输入法候选）；长文本或含引号 / `$` / 反引号的内容先写文件再用 `paste`。

**常见错误（Top 3）**

- `imgclick` 才是缩放截图上取坐标的正道（配同目录 `.map.txt`）；凭肉眼在缩放图上量像素是本工具最大的事故源。
- `focus` 或带 `--to` 再发键：不然按键可能落进别的窗口（包括你自己的终端）。
- `wins` 每次现读：窗口、前台、矩形随时在变，不要相信上一轮记下的选择器。

## 0. 先确认工具位置

本文中的 `$tool` 代表工具入口 `desktop.ps1`——在仓库里是根目录下的构建产物，装成技能后是 `scripts\desktop.ps1`：

```powershell
$tool = "<repo>\desktop.ps1"    # installed skill: <skill>\scripts\desktop.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File $tool help
```

每次调用都会新起一个 PowerShell 进程，2026-10-10 实测单次固定开销约 **1.5–1.9 秒**。所以：**第一次熟悉工具、或只有 1–2 个动作时**，逐步调用，方便读回显、方便发现哪一步不对；**3 个以上动作的固定链路**不要再一步步来——写成步骤文件用 `script` 一次跑完，见第 8 节。多步链路的最大浪费不是 token 而是这每次的进程开销。

## 1. 第一次操作的标准流程

按下面顺序做，不要跳过第 1、2、6 步：

```text
1. wins                         列出可见窗口，确认目标是否真的存在
2. info <sel> 或 win <sel>       确认目标窗口、前台状态和矩形；陌生界面先保存截图
3. find / uia-find / find-text   先定位控件或文字，不猜坐标
4. find-click / uia-click / click 执行动作；坐标动作尽量带 --to <sel>
5. type / type-in / paste         输入文本；按输入类型选择路径
6. read-text / find-text / assert-text / 再截图
                                回读完整结果，确认动作真的生效
```

最小例子（以记事本为例；把选择器换成当前真实窗口）：

```powershell
powershell -File $tool wins
powershell -File $tool info "记事本"
powershell -File $tool win "记事本" shots/notepad.png
powershell -File $tool find --target "记事本" "编辑"
powershell -File $tool type --to "记事本" "测试文本"
powershell -File $tool read-text "记事本" --max-lines 30
```

看到 `REFUSED` 或 `ERROR` 时，先读完整原因和建议的替代路线。守卫拒绝时不会发送按键或点击，不要用 `--force` 掩盖定位问题。

## 2. 什么时候必须截图

把截图当作观察工具，而不是最后才用的证据：

- 第一次接触陌生应用、窗口标题不确定，先 `wins`；目标范围不清楚时再 `win <sel>` 或 `shot`。
- 小字、小按钮或网页控件看不清时，用 `zoom x y w h [scale]`；不要反复手动裁剪和换算。
- 需要从图片里的像素点点击时，必须使用同一张 `win`、`rect` 或 `zoom` 产生的 `.map.txt`：`imgclick <图> <ix> <iy>`。只想查看换算结果用 `unmap`。
- 点击、输入、滚动或切换窗口后，界面状态不确定就再次截图或 OCR 回读；不要把“命令返回 0”当成“业务结果已出现”。
- OCR 返回 0 命中只说明这一次读取没有找到，不等于屏幕上绝对没有目标。看回显中的扫描范围、遮挡和复测信息，再换 `uia-find`、`find-text`、更小的区域或先 `focus`。

截图命令的坐标是屏幕像素。`--fit` 产生的图可能被缩放，肉眼量图像像素不能直接当屏幕坐标；用 `imgclick` 读取映射，或直接使用定位命令回显的 `centre=`。

## 3. 定位阶梯

按可靠性从高到低使用：

```text
find → uia-find → find-text / find-click → imgclick
```

- `find` 会先走 UIA，失败再走 OCR，并回显 `source=uia|ocr`。
- `uia-find` 适合按钮、输入框等有 UIA Name 的控件；需要确认控件结构时先 `uia-tree`。
- `find-text` / `find-click` 适合应用不提供可用 UIA 树、但文字可见的界面。
- `imgclick` 只用于你已经在截图中确认的像素点，并且必须有匹配的 `.map.txt`。

不要直接写“窗口左上角加一个凭感觉的偏移”。窗口移动、DPI、缩放、弹窗和遮挡都会让这种坐标失效。

## 4. 点击、输入和粘贴怎么选

- 已经有文字目标：优先 `find-click` 或 `uia-click`。
- 已知屏幕坐标：使用 `click x y --to <sel>`，让工具先确认前台和落点窗口。
- 中文或普通最终文本：优先 `type --to <sel> "文本"` 或 `type-in`。这条路径发送 Unicode 字符，不依赖当前中文输入法候选窗口。
- 能找到可写 UIA 控件：优先 `uia-settext <sel> <name> <utf8-file>`，不经过键盘和剪贴板。
- 长文本、包含引号/美元符号/反引号的内容：写入 UTF-8 文件后用 `paste --to <sel> file.txt`。
- 字面文本用 `type --to <sel> "文本"`；例如 `type --to "MyApp" "^a"` 会原样输入 `^a`。控制键用 `keys --to <sel> <spec>`；例如 `keys --to "MyApp" "^a"` 才是 Ctrl+A。数字 PID 是 `<sel>`，应放在 `--to` 后，不能和文本拼成 `type` 正文。
- 键盘组合键（例如保存、复制、Esc）：用 `keys`。不要用 `keys` 发送中文正文。
- 要把文件本身放进目标窗口（上传框一类）：用 `paste-file` 或 `copy-file`；不要把文件路径当成普通文本输入。验收示例只用自建自销的夹具——`paste-file --to "记事本" dtx-fixture.txt`，文件由本轮生成、本轮销毁。**项目红线 / hard red line：**不得向任何真实聊天、邮件或其他对面是人的会话窗口（微信 / QQ / 钉钉 / Slack / Outlook / 网页邮箱等）发送消息或文件，除非机主在本轮点名了那个收件人和那个文件。`paste` / `paste-file` / `copy-file` / `keys` / `type` 都会落进当前前台窗口，守卫通过只说明“键落进了哪个窗口”，不构成发送许可；已经开在屏幕上的聊天窗口不是夹具。

`activated=no (was fg)` 只表示窗口已在前台、跳过了再次激活；不表示没发送，也不证明字段获得焦点。窗口前台和编辑框焦点是两项证据。`uia-focus` 会调用 UIA `SetFocus`，但命令没有读回键盘焦点属性；不要把这条回执当作焦点证明。控件值可读时，操作后读回完整值；`uia-settext` 是直接设置 ValuePattern 并回读的另一条路径，不等同于键盘输入。对 OCR 可见字段用 `read-text` 或 `assert-text`；焦点或内容不可读时，说明限制并先看新截图，不把发送回执写成成功证明。

若前置界面有稳定可读文本，可用 `--guard-text` 或 `--guard-region` 锁住输入前提；焦点和值都不可读时，说明证据限制并用新截图定位。一次 `type` 未读回只说明这次调用没被当前方式确认，不足以判定所有 Qt／Electron 应用都不支持它；先复核这个控件和读取路径。

每次输入后都回读完整文本或截图确认。密码框、不可见控件和折叠区域不要使用 `--verify` 作为唯一证据。

### 已确认需要替换整个字段时

先确认目标窗口和具体编辑框，再确认焦点已落在该框；只有在确定要替换整段时才发送 Ctrl+A。`uia-focus` 的回执本身不是焦点读回：如果界面没有可核实的焦点状态，先截图确认插入光标或选中态，不确定就停下。

```powershell
focus "<sel>"
uia-focus "<sel>" "<field-name>"
keys --to "<sel>" "^a"
paste --to "<sel>" <utf8-file>
read-text "<sel>"    # 比对完整的新值；发送回执或尾部命中不足以证明整字段已替换
```

这只是明确的全字段替换配方，不是所有 `paste` 的默认前缀。若字段没有完整可读值，就记录无法验证的部分。

### 从列表打开一项

先确认目标窗口及列表行仍在，再点击唯一行，最后核验新标题或页面文字；有重复行时先确认目标序号再使用 `find-click --index <n>`。

```powershell
wins
assert-text "<sel>" "<unique-row-text>"
find-click "<sel>" "<unique-row-text>"
assert-text "<sel-after>" "<expected-page-title>"
```

图标没有文字且 UIA 不可用时，使用新鲜的局部截图与它的 `.map.txt` 映射后再 `imgclick`／`unmap`；OCR 不会判断图标代表什么。窗口或布局变化后重新截图。

## 5. 微信输入法说明

本工具支持在微信输入法处于中文模式时，把“最终中文文本”直接写入目标文本框：`type` / `type-in` 走 Unicode 投递，不需要先切换到英文，也不需要依赖微信输入法候选窗口。实测中文 IME 激活时可以落入普通文本控件。

这和“替你输入拼音并选择微信输入法候选词”是两件事。需要候选词、表情或输入法面板本身时，先截图确认面板，再用 `find` / `uia-find` / `find-text` 定位候选项，最后回读结果；不要假设候选窗口一定在固定坐标。

如果目标控件收不到 `type`：先 `info` / `focus` 确认窗口，网页表单可改用 `type-in` 并配合 `--tab`；能走 UIA 时改用 `uia-settext`；长文本改用 `paste`。`keys` 发送中文正文可能被输入法候选窗口吞掉。

## 6. 被拒绝、被遮挡或找不到时

```text
REFUSED foreground / outside / occluded  → 读原因，focus 或 win-restore 后重试
0 hits                                  → 读回显，换定位路线或缩小读取区域
截图提示 fitted/downscaled              → 只用 .map.txt + imgclick/unmap
窗口选择器多匹配                        → 改用 PID、proc:、class: 或更窄标题
动作后没有预期变化                      → 截图、read-text/assert-text、必要时 wait-stable
```

不要用旁路参数强行通过安全守卫。`--force` 只适用于你已经确认目标且明确接受失去守卫的场景，不是定位方法。

## 7. 一个可复制的安全配方

```powershell
# 只读探索
powershell -File $tool wins
powershell -File $tool info "记事本"
powershell -File $tool win "记事本" shots/notepad-before.png

# 定位后再动作（示例文字请替换为当前界面实际文字）
powershell -File $tool find "记事本" "编辑"
powershell -File $tool find-click "记事本" "编辑"
powershell -File $tool type-in 600 120 "要输入的中文"

# 回读，不凭感觉结束
powershell -File $tool read-text "记事本" --max-lines 40
powershell -File $tool win "记事本" shots/notepad-after.png
```

配方里换成任何对面是人的会话窗口都不算安全配方：收件人与文件必须由机主在本轮点名，见上一条红线。

开始前：目标窗口明确、截图或定位证据存在、落点在目标窗口内。结束后：完整回显已读、业务结果已回读、没有把猜测坐标当证据。

## 8. 多步链路：一个进程跑完（`script`）

固定链路（截图 → 定位 → 点击 → 回读）**不要一步一步调用**——每次都付一遍 1.5–1.9 秒的进程开销。写成步骤文件用 `script` 一次跑完，10 步链路从"十几秒"降到"两秒级"。

- 步骤文件是**一个 JSON 数组**。可直接照抄的样例在 `README.md`「批处理」段——那份样例由自测台逐字取出来跑 `script --dry-run` 验证过，是唯一被机器保证不会烂的样例，**不要自己另抄一份**（副本没人执行就会漂）。
- **先 dry-run**：`script <steps.json> --dry-run` 只打印计划、零执行。确认步骤顺序与目标窗口无误后再去掉 `--dry-run`。
- 每个步骤与单命令**共用同一套守卫**：`to` 走硬前台守卫（失败即中止整批，不是跳过该步）、`guard-text` / `guard-region` 在动作前断言上下文、`expectText` 等是动作后断言。批处理不是"绕过守卫的快速通道"。
- 自绘下拉、右键菜单这类"点开就可能消失"的流程，优先用**弹层存活自证** `require-popup`：它记录弹层基线并在此后每一步执行前复核，不满足就中止整批，避免把后续点击打到一个已经变了的世界里。
- **不要在批处理里省掉回读**：最后一步通常就该是 `read-text` / `assert-text` / `wait-stable`——它才是"业务结果已经出现"的证据；`script` 返回 0 只说明步骤都执行了。
- 重放走 `replay`，**默认 dry-run**；含脱敏占位符的步骤会被拒绝执行（这是设计，不是故障），要可重放就必须在当初执行那一步时显式带 `--log-payload`。

## 9. 与别的 agent 共用这台桌面

这台机器上可能同时开着多个 agent 会话，而**桌面、前台窗口和键盘焦点是全局唯一的资源**：

- **同一时刻只许一个 agent 操作真实桌面。** 两个会话并行点击/输入会互相抢前台，按键可能落进对方的窗口——工具守卫保证的是"这一下打给了谁"，它拦不住"另一边同时也在动"。
- 动手前先 `wins` **现读**：不要相信上一轮会话记住的窗口矩形、PID 或前台状态，它们在你拿到之前就可能已经变了。
- `press-down` 按住左键是**机器级状态**，跨进程也会残留。工具会在下一次调用的入口自动抬起并打 `WARNING`，但两个 agent 同时按住左键仍是竞争——交接前先确认没有按住态。
- `shots/actions.log` 是**共享**审计链，多个写入者会交错。要归因"这一步是谁做的"，看你自己当次调用的回显，不要只看日志尾部。
- 收尾还原：被你最小化的窗口请还原，测试用合成窗口请关掉，系统对话框一律"取消"，桌面上不要留测试文件。

更完整的参数、退出码和边界条件见 `README.md`、`skill/agent-computer-use/SKILL.md` 与同目录的 `reference.md`。
